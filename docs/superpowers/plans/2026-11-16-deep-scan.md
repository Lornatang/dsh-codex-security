# Deep Scan implementation plan

> Execute inline with `superpowers:executing-plans`; use a fresh reviewer before release.

**Goal:** Run bounded, isolated DSH review workers with durable cross-process recovery and a sealed, honest parent scan.

**Architecture:** A service-owned coordinator persists a campaign journal and uses local DSH activations. SQLite OS locks serialize campaign ownership, scan mutations and the shared index. Worker tools expose only a bound, verified source inventory, while a monotonic tool guard denies all other worker actions. Each accepted worker result is independently recorded and sealed before parent aggregation.

**Tech Stack:** TypeScript, Node.js >=22.19, built-in SQLite, DSH 0.2.2-rc.2/rc.3, Node test runner, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-16-deep-scan-design.md`.

## Global constraints

- Keep the npm name `@lornatang/dsh-codex-security`, preserve earlier uncommitted parity work and integrate the published v0.1.7 changes.
- No unsafe fallback when native/host capabilities, reliable lock semantics or worker confinement are unavailable.
- Automatic Deep does not accept diff targets; manual diff review remains available.
- Sealed scans are immutable and the parent may report partial coverage.
- Run Windows locally, the complete Linux/macOS/Windows matrix in GitHub CI, and the installed Codex artifact validator where available.

## Review focus

1. Two independent processes race to resume one campaign: exactly one owns it and a killed owner releases its lock.
2. Different scans update the shared index concurrently: neither scan disappears from the durable index.
3. A worker uses a scoped tool, transport, absolute path, traversal or swapped symlink: it cannot mutate the target or read outside the bound inventory.
4. An unfinished worker, process crash, timeout, changed target or conflicting duplicate must not produce a clean completed review.
5. A different session guesses a parent or child scan ID: every managed mutation fails without its recovery claim.
